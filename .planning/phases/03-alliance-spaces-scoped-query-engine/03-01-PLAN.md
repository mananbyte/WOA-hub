<objective>
Implement the Alliance data schema in PostgreSQL using Drizzle ORM, establish the 4-tier RBAC service (Owner, Admin, Member, Guest), enforce the single-primary-membership rule with multi-guest affiliation, build the multi-hub airport assignment registry, and expose secure REST API endpoints with automated integration tests.
</objective>

<threat_model>
ASVS Level 1:
- Role authorization: All alliance administrative actions (invite generation, application approval, airport assignment, group updates) verify user role is Owner or Admin in the alliance.
- Membership exclusivity: Database partial unique index strictly prevents a user from holding active Member/Admin/Owner roles in multiple alliances simultaneously.
- Route assignment boundaries: Verifies assigned airport codes match official WoA airports and enforces max 3 hubs per pilot.
</threat_model>

<tasks>
<task id="T1">
  <action>
    Update `src/db/schema.ts` with Drizzle tables for alliances:
    - Enums: `airport_model` ('assigned', 'flexible', 'hybrid'), `join_policy` ('open', 'approval', 'invite_only'), `alliance_role` ('owner', 'admin', 'member', 'guest'), `membership_status` ('active', 'pending', 'rejected'), `listing_visibility` ('public', 'alliance_only').
    - `alliances`: id, name, slug (unique), description, logoUrl, discordUrl, airportModel, joinPolicy, maxEscalationDelayHours (default 24), creatorId, createdAt, updatedAt.
    - `alliance_memberships`: id, allianceId, userId, role, status, applicationNote, createdAt, updatedAt.
      - Partial unique index: `idx_single_primary_alliance` enforcing that a user can have at most one active membership where `role IN ('owner', 'admin', 'member') AND status = 'active'`.
      - Unique index on `(alliance_id, user_id)` preventing duplicate memberships in the same alliance.
    - `alliance_assigned_airports`: id, allianceId, userId, airportCode (references `airports.code`), createdAt. Unique index on `(alliance_id, user_id, airport_code)`.
    - Enhance `listings`: add `allianceId` (references `alliances.id`, nullable), `visibility` (`public` or `alliance_only`), `autoEscalateDelayHours` (int, nullable), `escalatedAt` (timestamp, nullable).
    - Push schema changes to PostgreSQL using `npx drizzle-kit push`.
  </action>
  <verify>
    npm run db:push
  </verify>
</task>

<task id="T3">
  <action>
    Implement `AllianceService` in `src/services/alliance.service.ts`:
    - `createAlliance(userId, input)`: Creates alliance and automatically inserts creator as active `owner`.
    - `getAlliances(filters)`: Lists public alliances with member count and operating model.
    - `getBySlug(slug)`: Returns alliance dossier with member count and public metadata.
    - `applyOrJoin(allianceId, userId, note, inviteCode)`: Handles joining based on policy:
      - If 'open': immediately creates active 'member' (or 'guest' if requested).
      - If 'approval': creates pending application.
      - If 'invite_only': validates invite code token before joining.
      - Enforces that user is not already an active member of another alliance (guests exempt).
    - `reviewMembership(allianceId, actorId, targetUserId, status, role)`: Verifies actor is Owner/Admin before updating status.
    - `assignAirport(allianceId, actorId, targetUserId, airportCode)`: Verifies user is member of alliance, checks airport exists, checks count < 3, and inserts assignment.
    - `getRouteMatrix(allianceId)`: Calculates coverage across all 10 WoA hubs, lists assigned pilots per airport, and computes route gaps.
  </action>
  <verify>
    test -f src/services/alliance.service.ts
  </verify>
</task>

<task id="T4">

    - `GET /api/alliances`: List directory of alliances.
    - `GET /api/alliances/:slug`: Public dossier by slug.

    - `DELETE /api/alliances/:slug/airports/:code`: Remove assigned hub.
    - `GET /api/alliances/:slug/matrix`: Route coverage matrix.
