<objective>
Implement complete user authentication and player profile management: email/password registration with mandatory Discord username, secure login with JWT token generation, auth middleware, WoA Player ID profile binding, public player profile retrieval, and automated test coverage.
</objective>

<threat_model>
ASVS Level 1:
- Password storage: Passwords must be hashed using bcrypt with salt rounds >= 10. Raw passwords must never be stored, logged, or returned in API responses.
- Session hijacking: JWT tokens must be signed with a strong secret key (`JWT_SECRET`) and validated on protected routes.
- Input validation: Zod schemas must sanitize and validate email format, password complexity (min 8 chars), and Discord username strings before database operations.
- Information leakage: Public profile endpoints must exclude sensitive columns (`password_hash`, private email).
</threat_model>

<tasks>
<task id="T1">
  <action>
    Create input validation middleware and schemas in `src/middleware/validate.ts` using Zod:
    - `registerSchema`: validates `email` (valid email), `password` (min 8 chars), `discord_username` (min 2, max 32 chars, no @ prefix or sanitized), and optional `woa_player_id`.
    - `loginSchema`: validates `email` and `password`.
    - `updateProfileSchema`: validates `woa_player_id` (alphanumeric string).
    Create `src/middleware/auth.ts`:
    - JWT verification middleware extracting `Authorization: Bearer <token>`.
    - Attaches `req.user = { userId, email, discordUsername }` or returns HTTP 401 Unauthorized.
  </action>
  <verify>
    npx tsc --noEmit src/middleware/auth.ts src/middleware/validate.ts
  </verify>
</task>

<task id="T2">
  <action>
    Implement `src/services/auth.service.ts` and `src/services/user.service.ts`:
    - `authService.register()`: checks for existing email, hashes password with bcrypt (10 rounds), inserts new user record, and returns signed JWT with sanitized user object.
    - `authService.login()`: fetches user by email, verifies password using bcrypt.compare, returns signed JWT with user details, or throws HTTP 401 on invalid credentials.
    - `userService.getProfile(userId)`: returns user's profile including WoA ID, Discord username, reputation score, and contract stats.
    - `userService.updateWoaId(userId, woaPlayerId)`: updates the user's WoA Player ID.
    - `userService.getPublicProfile(targetUserId)`: returns public safe profile data (excludes password_hash and email).
  </action>
  <verify>
    npx tsc --noEmit src/services/auth.service.ts src/services/user.service.ts
  </verify>
</task>

<task id="T3">
  <action>
    Implement REST endpoints and Express server wiring:
    - `src/routes/auth.routes.ts`:
      - `POST /api/auth/register` (uses `registerSchema`)
      - `POST /api/auth/login` (uses `loginSchema`)
      - `GET /api/auth/me` (protected via `requireAuth`)
    - `src/routes/user.routes.ts`:
      - `PATCH /api/users/me` (updates `woa_player_id`, protected)
      - `GET /api/users/:id` (public profile)
    - `src/app.ts`: Express application setting up `cors`, `express.json()`, request logging, route mounting, and global error handler.
    - `src/server.ts`: Listens on `PORT` (default 3000) using `dotenv`.
  </action>
  <verify>
    npx tsc --noEmit src/app.ts src/server.ts
  </verify>
</task>

<task id="T4">
  <action>
    Write integration tests in `tests/auth.test.ts` covering:
    - User registration returns HTTP 201 with JWT token and user info containing `discord_username`.
    - Duplicate registration with same email returns HTTP 409 Conflict.
    - User login with valid credentials returns HTTP 200 with valid JWT.
    - User login with invalid password returns HTTP 401 Unauthorized.
    - Protected endpoint `GET /api/auth/me` returns 401 without Bearer token, and 200 with valid token.
    - Updating WoA Player ID persists value and is reflected in profile.
    - Public profile `GET /api/users/:id` returns WoA ID and Discord username but omits `password_hash` and `email`.
  </action>
  <verify>
    npx tsx tests/auth.test.ts
  </verify>
</task>
</tasks>
